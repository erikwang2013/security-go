## 2. Исправленные баги

### Баг #1 [Критический] `storage/file.go:101` — ошибка JSON-сериализации молча игнорировалась

**Проблема**: в методе `Close()` вызов `data, _ := json.Marshal(out)` игнорировал ошибку сериализации. Если JSON-сериализация завершалась с ошибкой, `data` оказывался nil, и `os.WriteFile` записывал пустые данные, **из-за чего терялись все персистентные данные**.

**Исправление**: проверять возвращаемую ошибку `json.Marshal` и немедленно возвращать error при сбое.

```go
// 修复前
data, _ := json.Marshal(out)
return os.WriteFile(f.path, data, 0644)

// 修复后
data, err := json.Marshal(out)
if err != nil {
    return err
}
return os.WriteFile(f.path, data, 0644)
```

### Баг #2 [Критический] `httpval/content_type.go:34` — пустой AllowList пропускал все Content-Type

**Проблема**: условие `if len(c.Allowed) == 0 || c.Allowed[mt]` означало, что при пустом AllowList **пропускаются все Content-Type**. Безопасным значением по умолчанию должно быть deny-all.

**Исправление**: убрано условие `len(c.Allowed) == 0`, пустой AllowList попадает в ветку отказа.

```go
// 修复前
if len(c.Allowed) == 0 || c.Allowed[mt] {
    return &security.Result{Name: c.Name(), Detected: false}
}

// 修复后
if c.Allowed[mt] {
    return &security.Result{Name: c.Name(), Detected: false}
}
```

### Баг #3 [Средний] `protocol/xxe.go:15` — `&[a-z]+;` ложно сопоставлялся со всеми легальными HTML/XML-сущностями

**Проблема**: регулярное выражение `(?i)&[a-z]+;` сопоставлялось со всеми стандартными ссылками на сущности (`&amp;`, `&lt;`, `&gt;` и т.д.), из-за чего любой запрос, содержащий легальный HTML/XML, ложно помечался как XXE-атака.

**Исправление**: диапазон сужен до префиксов известных вредоносных протоколов.

```go
// 修复前
regexp.MustCompile(`(?i)&[a-z]+;`),

// 修复后
regexp.MustCompile(`(?i)&(?:xxe|file|http|ftp|gopher|dict|data|expect);`),
```

## 3. Обнаруженные второстепенные проблемы (не исправлены, требуют оценки)

### Проблема #1: пакет `all` не покрыт тестами

У функции `RegisterAll()` в `all/all.go` нет ни одного теста. Следует добавить тесты, проверяющие, что все зарегистрированные детекторы корректно вызываются.

### Проблема #2: тесты пакета `httpval` дописаны ✅ (решено)

Добавлен `httpval/httpval_test.go` (32 тест-кейса), покрывающий `BodySize` (7 тестов), `ContentType` (7 тестов), `CSRFOrigin` (8 тестов), `IPBlacklist` (6 тестов), `Method` (3 теста). Включает граничные значения, некорректные входные данные и проверку deny-all при пустом AllowList.

### Проблема #3: в `data/data_leak.go` регулярное выражение для кредитных карт слишком широкое

`\b(?:\d[ -]*?){13,16}\b` сопоставляется с любой последовательностью из 13-16 цифр.

### Проблема #4: подмодуль `storage/redis/` неполон

- В `go.mod` отсутствует объявление зависимости от родительского модуля
- Отсутствует файл `go.sum`

### Проблема #5: несоответствие стиля receiver между пакетами protocol и injection

- Пакет `injection` использует указательные receiver: `func (d *XSS) Name() string`
- Пакет `protocol` использует value-ресиверы: `func (d CORS) Name() string`

### Проблема #6: `injection/xss.go` — `&#x?[0-9a-f]+;?` сопоставляется с легальными числовыми HTML-ссылками на символы
